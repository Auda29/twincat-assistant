# Alpha candidate 0.2.0-preview.2

This candidate combines the distribution feature boundary and product naming
with the installer-selected runtime, profile recovery journal and direct-host
acceptance tooling. It has actual code changes relative to the first CI
candidate at `46f96a17697128721c6c1651a8a0f09dc2297d43`; it is not an
update/rollback fixture made by relabelling that package.

The application package uses SemVer `0.2.0-preview.2`. Both VSIX manifests and
the native host AssemblyVersion/FileVersion use numeric `0.2.0.2`. The 64-bit
payload remains an unaccepted prototype target. Numbering does not grant host
support or a completed alpha acceptance. The installed unowned prototype stays
`0.1.9` until a separately recorded installer transaction changes it.

The first real Windows CI candidate is from
[run 42034006930](https://github.com/Auda29/twincat-assistant/actions/runs/42034006930).
Its `reviewed-input` and hosted `windows-2022` jobs both succeeded. The hosted
job ran protected packaged startup, both real MCP probes on synthetic data,
restart/state preservation, installer build and embedded-payload verification.
Artifact `13418347605`, `windows-package-candidate`, has 518586701 bytes and
ZIP SHA-256 `1d62ed49619ac6d9debb61e6b02f420a39f5f26ff0af9b7751c1235763c73ef1`.
That evidence applies to its exact CI source SHA above, not to this later
candidate. A new build and CI run are required for this version.

## Integrated local build

The combined source UI was genuinely rebuilt with `build-source-runtime.mjs
--ui-only`, reusing only the validated unchanged pinned Core executable. The
source receipt was regenerated by that build. The x86 host and Windows helper
were then rebuilt with the pinned SDK 8.0.425. All 151 native regressions and
19 targeted host/inventory/delivery tests passed. The host build retains six
existing VSTHRD010 warnings. Assembly, file and generated VSIX versions were
read back as `0.2.0.2`.

The actual package at `artifacts/alpha-final-20261105/application` contains
22085 manifest entries. Its application-manifest.json SHA-256 is
`12f0827fe13cfb1bdd18c54b56f9576b178de6d4c91803f339cf699ec5b03657`.
`node scripts/test-built-application.mjs <that-absolute-package-directory>`
passed protected startup, excluded endpoint checks, both real MCP probes on
synthetic files, restart, state preservation and unchanged-package checks.
No provider or PLC action was part of this smoke test.

The combined serial Node run executed 141 tests: 140 passed, and one menu
contract still expected the historical `0.1.9` VSIX literal. That assertion was
corrected to require agreement of the native file/assembly/VSIX versions and
the application/host SemVer. Both tests in that file then passed. This is a
targeted rerun after a test-only correction, not a claim that the initial
141-test run was fully green.

After integrating C1 and strengthening the code-evidence cases, the complete
combined suite was run again with `node --test --test-concurrency=1
tests/*.test.mjs`: 145/145 passed, zero skips, 166.79 seconds. The local log is
`local-data/alpha-host-baseline-20261105-140304/c1-full-node-tests.log`.
The actual packaged Engineering accessor probe also passed and confirms
flattened Get/Set output at the unchanged pinned Engineering revision; C1
reports the missing boundaries. The above local package smoke preceded the C1
source refresh. A final C1 package/installer CI run and actual C1-to-C0 policy
rollback are still required; neither is inferred from these unit results.

The reviewed producer baseline is
`d5a227ac072891bfeb6eb67c40e842e9d2c6346e`, whose runtime/native/dependency files
match these package inputs. The producer's separate preparation record binds
that source and manifest; it is not yet a successful CI result for this version.
